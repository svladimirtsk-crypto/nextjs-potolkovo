Принцип, который соблюдался в каждом коммите: **в `lib/` уезжает только то, что не требует React**

Почему коммиты 7 и 8 сведены в один: правки футера были внесены в оркестратор, пока шёл полный
E2E-прогон вкладок, и разделить их по коммитам без хирургии патчей стало нельзя. Проверки выполнены
для обоих состояний раздельно (вкладки — полный E2E 180/12, футер — целевой прогон 8 спеков 55/9).

### Ключевые правила, которые перестали быть «памятью» и стали тестами

- **Приоритет входа на вкладку:** `step1CatalogView` > `initialLightingTab` > `entryMode`
  (`resolveBaseTab`). Оверрайд пользователя действует, только пока не сменился базис
  (`override.base === baseKey`), иначе вход из каталога «залеплял» выбор человека.
- **Пустое «Выбранное»** деградирует в «Каталог» (`shownCatalogViewOf`) — показывать пустой список нечем.
- **Две разные мутации корзины:** `applyProfilePlan` (T-032) **задаёт** количество (`next[id] = piece.qty`),
  а `applyKitSuggestions` (T-042) **складывает** (`(next[id] ?? 0) + qty`). Перепутать их — значит либо
  удвоить метраж при повторном «Собрать автоматически», либо не доложить питание к уже выбранному свету.
- **Блокировка по БП CLARUS** в мастере несётся дескриптором футера, а на вкладке «Каталог» — самим
  действием `finishAction` (`Нужен блок питания`). Это два разных места, и теперь оба зафиксированы.
- **Снимок заявки из каталога страницы:** пустая корзина возвращает **прежний** объект снимка (записи в
  стор нет, лишнего рендера нет) и **не перезаписывает** существующий `leadSource` — источник
  привлечения важнее источника «каталог на странице света».
- **«Назад» с точек** (`backFromPoints`) — копия правила для ламп без первой ветки; раньше была
  инлайн-стрелкой в JSX.

## 6. Ограничения и что осталось

1. **Эффект автоочистки «осиротевшего» трека (T-024) намеренно оставлен в оркестраторе.** Правило
   `decideOrphanTrackAction` — чистое и вынесено, но сам эффект с `useRef` + `setState` живёт в
   компоненте, чтобы оставаться под стражем `check-effect-setstate.mjs`. Перенос эффекта в `lib/`
   вывел бы его из-под проверки — это ухудшение контроля, а не кода.
2. **Коллизия имён `WizardStep`** (не исправлена, отдельный долг): `lib/calculator-modal-types.ts` —
   числовой `0 | 1 | 2` (шаги модалки), `lib/lighting/resolve-initial-step.ts` — имена экранов мастера
   света. В новых файлах импортируется как `ModalStep` / `WizardStep` с явным указанием источника.
3. **Шаг 1 остаётся оркестратором, а не отдельным автоматом со своим редьюсером.** `PHASE-C-REPORT.md`
   предупреждал, что полный вынос состояния мастера (`wStep`, `wOverride`, автосборка профиля) — это
   перепроектирование. Сделан промежуточный вариант: правила и переходы — чистые функции и хуки,
   состояние оверрайда (`wOverride`) осталось в компоненте, потому что его сеттер нужен и корзине
   (выбор профиля меняет систему). Дальнейший шаг возможен, но требует отдельной задачи с планом отката.
4. **`data/page-dates.json`** меняется при каждой сборке (даты prerender). В коммиты задачи не включался;
   перед пушем приведён к состоянию `HEAD`.
5. **Проверка на проде не выполнялась** — задача не подразумевает деплоя; прод собирается из `main`,
   мерж `quizv2ver1 → main` делает владелец.
6. Окружение песочницы между ходами обнуляется (`node_modules`, `.next`, кэш браузеров, `.git/config`,
   системные библиотеки Chromium). Перед финальным прогоном восстановлены: `npm ci`, `npx playwright
   install chromium`, `apt-get install libnspr4 libnss3 …`, `git config user.*`, `git remote add origin`.
   На содержимое репозитория это не влияет.
