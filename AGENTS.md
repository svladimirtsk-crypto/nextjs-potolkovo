# Работа с ПОТОЛКОВО

Сначала прочитайте `docs/current/README.md`, затем `STATUS.md`. Единственные действующие ТЗ: `BRAND-REDESIGN-TZ-V8.md` и `TECHNICAL-TZ-V8.md`. Команды/эксплуатация/реестр skips — `docs/current/RELEASE-OPERATIONS.md`. Старые ID в коде сохраняют происхождение, но не делают прежние документы действующими.

- Компания средний+, основатель + привлечённые мастера / партнёрские бригады. Не возвращать позиционирование мастера-одиночки или вымышленного большого штата.
- Продолжать в `feat/company-rebrand-v7-preview`. Main автоматически выпускается в production. Без отдельного явного согласования выпуска не создавать PR в main и не выполнять merge/push туда. Не делать force-push.
- Сохранить 9 URL услуг, тарифы, формулы, явные пресеты, draft и контекст заявки. Не создавать второе расчётное ядро ради дизайна.
- Теневые, парящие потолки, линии, треки и карнизы — значимые направления. SMART-консультация не означает подтверждённую BOM, совместимость, наличие или торговую модель.
- Не переписывать цитаты отзывов. AI-иллюстрации маркировать; не подменять ими реальные кейсы. Фотографии и исходные сведения не считать подтверждёнными без источника и прав. Лицензии/ассеты: `design/brand/v7/README.md`.
- Не выдумывать реквизиты, роли, сроки, гарантии, stock, историю или совместимость. Юридические абзацы менять только по согласованной правовой основе.
- Приоритет пользователя — бренд/дизайн. Standalone reload корзины отложен; не начинать его вместо брендового этапа.
- Для preview отключать Метрику на build-time и lead/Telegram/live-feed на runtime. Тесты — только с изолированной БД и fake-получателями, не production.
- Не сохранять PAT/секреты в файлы, коммиты, логи или URL remote. Авторизация только на время нужной операции.
- Для кода/UI: lint, TypeScript/build, unit с PostgreSQL, flow, catalog/prebuild guards, bundle, полный E2E и strict flaky check. Axe не заменяет ручные устройства/reader/zoom. Для docs-only — проверка ссылок, покрытия требований, отсутствия изменений runtime и сохранности исходников; не выдавать прежний QA за новый.
- Не плодить отчёты по каждому шагу: обновлять `STATUS.md`, актуальные задачи и компактные доказательства в `docs/evidence/latest-qa/` с SHA/датой. Устаревшие активные документы удалять после переноса требований; историю Git и пользовательские оригиналы сохранять.
