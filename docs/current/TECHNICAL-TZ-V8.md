Дата: 14.10.2026. База кода: `3dd20cd`. Работать только в `feat/company-rebrand-v7-preview`.

Это **перенос незакрытых требований**, а не повторный live-аудит поставщика или production. Дизайн — в [BRAND-REDESIGN-TZ-V8.md](BRAND-REDESIGN-TZ-V8.md). Здесь сохранены 36 технических направлений с исходными критериями и обновлёнными статусами; старые F6-ID заменены T8-ID, соответствия — [LEGACY-MAP.csv](LEGACY-MAP.csv).

## Границы и порядок

- P0-R блокирует выпуск затронутого коммерческого/инженерного сценария, но не работу над preview и айдентикой. Не все 36 задач нужно выполнить до консультационного бренд-релиза.
- Приоритет пользователя — ребрендинг. Не начинать persistence автономной корзины вместо дизайна: задача отложена, но не закрыта.
- Не удалять прежний API/reducer/цены/пресеты и принятые заявки. Любая денежная/инженерная правка — отдельный объём с regression tests.
- Исторические численные наблюдения ниже относятся к снимкам аудита 14.10.2026 на базе `7f1b5cf`, а не к сегодняшнему складу/цене. При исполнении заново получить данные и перепроверить дефект на рабочем SHA.
- Эксплуатационные параметры — [RELEASE-OPERATIONS.md](RELEASE-OPERATIONS.md). Для тестов запрещены production-БД, токены каналов и немаркированные реальные заявки.
- Для каждой задачи: ожидаемый/фактический результат, владелец, изменённые файлы, тест до/после, QA, миграция и безопасный откат. Никакого «закрыто» только по отчёту прошлой версии.
- Процесс: факты/право → данные и единицы EKS → электрическая совместимость/экономика → versioned quote/intent → guided UI → пилот → масштабирование. Консультационная страница уже существует и не обязана ждать полноценной торговли SMART.

### T8-007 · PT-021: доверенный IP и размер запроса

**Статус:** ПЕРЕПРОВЕРИТЬ НА ТЕКУЩЕМ SHA: технический аудит не является новой проверкой proxy/ingress.

**Приоритет:** P1. **Владелец исполнения:** Backend + DevOps. **Зависимости:** T8-002.

**Работа:** Документировать trust boundary reverse proxy. Ввести лимит тела до полного JSON parse, включая chunked/no Content-Length; sane timeout и rate-limit по нескольким сигналам без блокировки всего неизвестного IP.

**Приёмка:** 413 на oversized declared и streaming body, 400 на битый JSON, 429/Retry-After на лимит; поддельный внешний XFF не обходит ограничение при фактической конфигурации proxy. Интеграционный тест через proxy и распределённое хранилище при нескольких инстансах.

**Откат / ограничение:** Согласованные proxy/app лимиты; не отключать всю защиту ради одного клиента.

**Работа:** Server-issued capabilities, разделение build/runtime flags, audit log изменения. Backend/schema сперва, затем новый UI; support старых вкладок/drafts. Sales, auto-kit, smart claims и оформление выключаются независимо.

**Приёмка:** Kill-switch отключает новую продажу в заданный TTL без пересборки JS; backend тоже запрещает недоступную операцию. Старый клиент/новый сервер и новый клиент/несовместимый сервер проверены. Нет silent stripping платных smart-полей; rollback не удаляет лиды/quotes и миграции совместимы.

**Откат / ограничение:** Переключить capability на legacy/consultation; contract-удаление полей только после истечения поддерживаемых клиентов.
