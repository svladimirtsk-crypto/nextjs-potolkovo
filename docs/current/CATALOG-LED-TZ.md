# ПОТОЛКОВО · ТЗ на каталог лент, комплектующих и подбор по метражу

**Редакция:** 14.10.2026. **Основание:** [CATALOG-LED-AUDIT.md](CATALOG-LED-AUDIT.md). **Статус:** проект реализации; раздел и инженерный подбор ещё не внедрены. Только preview, без автоматического merge/deploy в main.

ТЗ конкретизирует T8-010/011/012/013/014/015/016/019/020/021/025/026/027/030/031. PT-020…049 остаются действующей очередью, нумерация не заменяется. Обозначения CAT-A в аудите — находки, а тесты ниже — критерии, не новая независимая система задач.

## 1. Цель и границы

Лид без электротехнической подготовки должен:

1. Найти нужный раздел по назначению света или названию товара.
2. Понять, что он покупает: метр, катушку, штуку или комплект; что включено в цену.
3. Указать метраж **парящего контура, световой линии, подсветки карниза** без повторного ввода известных данных калькулятора.
4. Выбрать желаемое управление человеческими словами.
5. Получить объяснимый предварительный состав: лента, питание, управление и обязательные комплектующие, либо понятный список вопросов специалисту.
6. Передать этот состав в заявку без потери комнат, зон, intent, источника и версии расчёта.

Не обещать «все товары со всем совместимы», «любой пульт подойдёт», «любой TUYA работает с Алисой». «Все варианты управления» означает полную понятную карту возможностей с разделением **подтверждено в ассортименте / требует проверки / доступно по проекту**, а не активные кнопки несуществующих функций.

Сохранять существующий бренд, URL услуг, оба текущих пути заказа, source/EntryContext, подтверждённые параметры, requestId/consent. Standalone reload корзины остаётся отдельной ранее отложенной задачей; не считать его автоматически разрешённым этим ТЗ.

## 2. Информационная архитектура

### Страница каталога

**Первый экран:** «Каталог освещения и комплектующих». Короткое объяснение: «Выберите товары или подберите комплект ленты по метражу. Окончательные состав, наличие и монтаж подтверждаем перед заказом».

Два явных действия:
- **Подобрать ленту и питание** — guided-путь по задаче/метражу.
- **Перейти к товарам** — поиск и категории без принудительного калькулятора потолка.

Навигация: Ленты и комплектующие / Трековые системы / Точечные светильники / Люстры / Лампы / Монтажные комплектующие. Внутри первой группы: **Ленты · Блоки питания · Управление · Пульты и панели · Подключение · Профили и рассеиватели**. Шлюзы и усилители имеют отдельный подтип, а не теряются в «Прочем».

Трековый образовательный блок COLIBRI/CLARUS/ART — в соответствующем разделе или под раскрытием. Не заставлять покупателя ленты изучать магнитные треки до выбора товара. Существующий URL `/uslugi/prodazha-trekovogo-osveshcheniya` не удалять; добавление общего SEO-хаба согласовывать отдельно.

**Порядок блоков:** вход и два пути → категории/поиск → товары или подбор → текущий комплект → доставка/монтаж/проверка → FAQ. Большие обучающие материалы и кейсы — ниже/по запросу, не между намерением и товаром.

### Внутри калькулятора

Использовать ту же таксономию, поиск и карточку характеристик. «Ленты и комплектующие» доступны независимо от ответа про карниз. Метраж конкретной задачи выводится как контекст: «Гостиная · парящий контур · 17 м», а не скрытый фильтр.

Показывать «Подходит для текущей зоны» только при проверенных условиях. Отдельно дать «Посмотреть весь каталог»; несовместимый товар не добавлять молча в текущую зону. Для самостоятельного просмотра можно сохранить товар как отдельную позицию с явным предупреждением, без статуса полного комплекта.

## 3. Категории и карточки

| Тип | Единица и количество | Основные признаки |
|---|---|---|
| Лента | отдельно mounted m / sale m или reel; шаг продажи из политики поставщика | Mono/CCT/RGB/RGBW/RGB+CCT/SPI; U; подтверждённые max Вт/м; CCT/CRI; ширина; IP; шаг реза |
| БП | целые pcs | CV/CC, выходное U, мощность и ток, исполнение/габариты, derating, охлаждение/шум, способ диммирования |
| Диммер/контроллер | целые pcs | поддерживаемые режимы, U, I каждого канала и общий, входы/протоколы, экосистема/пульт |
| Пульт/панель | целые pcs | управляемые функции, зоны, протокол/семейство, питание самого пульта, подтверждённые пары |
| Набор | целые kit | перечисление включённых компонентов; не добавлять пульт/БП повторно |
| Соединение/усиление | pcs/m по конкретному товару | ширина/контакты/распиновка, допустимый ток, условия, протокол усилителя |
| Профиль/рассеиватель | длина/штучный хлыст отдельно | назначение, ширина канала, геометрия, тепловой допуск, экран, крепёж, доступ обслуживания |

Лицевая сторона карточки: изображение → понятное имя → 3–5 решающих характеристик → цена **за конкретную единицу** → наличие с датой/условием → действие. Артикул рядом, но не вместо имени. «Новинка» не должна занимать место напряжения/типа/единицы.

Для ленты показывать обе связи: «катушка 5 м — X ₽; эквивалент Y ₽/м» **только после подтверждения ценовой единицы**. Установлено 6 м ≠ куплено 6 м, если продажа катушками. Нельзя принять цену XML за метр по слову «лента».

Поиск: токены независимо от порядка; нормализация `Wi-Fi/WIFI`, `24 В/24V`, разумных пробелов/дефисов; точный приоритет SKU; проверенные aliases. Явно обозначить область поиска, показывать переход к другим категориям и сохранять запрос. Не транслитерировать все vendorCode без контроля коллизий.

## 4. Данные: блокирующий контракт до автоматизации

### Единый импорт

XML → raw archive + hash → нормализация → проверка → diff/review → **атомарная публикация catalogVersion**. Сохранять last-known-good. Дата источника, часовой пояс, retrievedAt и publishedAt — разные поля. Нельзя обновлять «свежесть» старого snapshot датой сборки сайта.

Обработать XML без categoryId (в текущем снимке их нет у всех 696 офферов); категории получать из документированного маппинга/пути с review, не по произвольному совпадению слова. Контроллер/пульт/БП не превращаются в LED_STRIP из-за общего пути `/svetodiodnaya-lenta/`.

Стабильная идентичность: supplier + externalOfferId + проверяемая сущность/ревизия; vendorCode/GTIN — атрибуты и aliases. Проверить 186 найденных смен артикулов, в том числе 58 в LED-группе. Не мигрировать автоматически, если отличаются упаковка, характеристики или ревизия.

### Обязательные поля

Общие: productId, supplierId, offerId, currentVendorCode, aliases, barcode, productType, saleUnit, packQty, minSaleQty, quantityStep, priceBasis, retailPrice, currency, VAT/status при применимости, source timestamps, catalogVersion, stockByWarehouse, availabilityState, evidence/reviewer.

**Лента:** voltageDc, supplyMode, maxPowerWm, powerBasis/allChannelsPolicy, perChannelPowerWm, stripMode, channelCount, polarity/pinout, widthMm, cutStepMm, reelLengthMm, maxFeedLengthMm, maxCurrentRun, CCT/CRI/lightFlux, IP, thermalMountRequirements.

**БП:** outputMode CV/CC, outputVoltage, ratedOutputPowerW, ratedOutputCurrentA, acceptedInputRange, deratingRule/evidence, dimensions, mounting/IP/temperature, cooling/noise, dimmingInput, minLoad, inrush/protection requirements.

**Контроллер:** acceptedVoltageRange, supportedStripModes, outputTopology, maxCurrentPerChannelA, maxCurrentTotalA, inputConnectorCurrentLimits, thermal limits, PWM characteristics при необходимости, localInputs, RF family/protocol, Wi-Fi/Bluetooth/Zigbee/Matter capabilities, ecosystem/region/firmware, internetDependency, powerRestoreBehavior, compatibleRemoteIds + evidence.

**Пульт:** controlFamily, compatibleControllerIds, functions, zones, ownPowerSource, pairing/maxDevices, local/offline behavior. «4 зоны» и «4 силовых канала» — разные поля.

У каждого инженерного поля хранить источник и статус: `unknown / title_only / label_observed / datasheet_verified / bench_verified`. Разбор названия и фото маркировки полезен для кандидатов/отбраковки, но **title_only или label_observed сами по себе не дают verified BOM**. Отсутствующее значение не превращается в false/0. Облегчённый index должен сохранять необходимые типы, единицы, verified capabilities и версию, а не только название/цену.

## 5. Подбор по задаче и метражу

### Путь лида — четыре понятных шага

1. **Где нужен свет:** парящий контур / световые линии / карниз / другая задача; комната и новый или готовый потолок.
2. **Как должен светить:** мягкая подсветка / основной свет; тёплый/нейтральный белый / регулируемая температура / цвет + отдельный белый. Не обещать RGB как эквивалент качественного белого света.
3. **Сколько и как управлять:** известный метраж подставлен из расчёта; пользователь подтверждает длину и число независимых зон; выбирает выключатель / яркость / пульт / смартфон / голос. «Не знаю» ведёт к подбору, а не тупику.
4. **Состав и объяснение:** лента, БП, управление, обязательные компоненты; что уже включено в потолочную ставку; какие данные надо уточнить. Телефон не требуется только для просмотра предварительного состава/ориентира.

Не спрашивать у новичка ток канала и CV/CC. Эти данные берутся из проверенной библиотеки. Не подтверждённые длина/модель/условия означают предварительный подбор.

### Объектная модель

`Project → Room → Feature → StripRun` и отдельно `ControlZone / PowerCircuit`.

- Feature: floating / lightLine / cornice; ссылка на соответствующий параметр действующего расчёта.
- StripRun: модель, фактическая длина, число рядов, отрезки/кратность реза, профиль и способ отвода тепла.
- ControlZone: какие отрезки управляются вместе, режим и канал/контроллер, выбранные интерфейсы.
- PowerCircuit: обслуживаемые ветви, нагрузка, БП, трассы и ограничения.

Одна комната может иметь несколько независимо управляемых зон. Несколько зон могут питаться от одного БП только по проверенной схеме; число БП не равно числу катушек и не обязано равняться числу зон. Электрически объединять выходы БП/контроллеров без допуска производителя запрещено.

**Важно:** 6 м световой линии с двумя рядами ленты дают 12 м нагрузки, а не 6 м. Закупочный запас и неустановленные остатки катушки в электрическую нагрузку не включаются. Изменение метража обновляет затронутые позиции, а не теряет ручной выбор управления.

## 6. Инженерные правила расчёта

Это требования к программному подбору, не инструкция самостоятельного подключения к сети. Окончательная схема, питание, защита, кабели и монтаж проверяются квалифицированным специалистом по конкретным паспортам и условиям объекта.

### Мощность и ток

Для подтверждённых установленных отрезков:

- `P_led = Σ(L_installed_i × rows_i × p_max_i)`.
- `P_load = P_led + P_aux`, где P_aux — подтверждённое собственное потребление устройств, питающихся от того же БП; не дублировать саму нагрузку ленты.
- `P_nominal × D(T, input, mounting) ≥ P_load × K_policy`.
- `I_load = P_load / U_dc`; проверить также номинальный выходной ток БП и ограничения каждой ветви.

`D` — применимое снижение допустимой мощности по паспорту, не универсальное число. `K_policy` — явно утверждённый проектный запас. В примерах ниже `K=1.25`, `D=1`, P_aux=0: это **учебная политика, не подтверждение EKS-комплекта**. +20% к нагрузке и загрузка БП не более 80% — не одна формула: коэффициенты 1.20 и 1.25 соответственно.

КПД не подставлять вместо запаса: `P_input ≈ P_output / η` относится к входной стороне и потерям. Температурные/монтажные ограничения могут потребовать другой корпус, место или деление на цепи даже при достаточных номинальных ваттах. Основания: [2](https://arlight.ru/support/recommendations/), [паспорт с отдельными output/efficiency/derating](https://www.meanwell.com/Upload/PDF/LPV-100/LPV-100-SPEC.PDF).

| Условный пример с подтверждёнными Вт/м | LED-нагрузка | Требуемый номинал при K=1.25, D=1 | Результат только по мощности |
|---|---:|---:|---|
| 5 м × 10 Вт/м | 50 Вт | 62.5 Вт | 60 Вт недостаточно; 72/100 Вт — кандидаты, не финальная совместимость |
| 8 м × 12 Вт/м | 96 Вт | 120 Вт | 100 Вт недостаточно; 150 Вт — кандидат |
| 17 м × 14.4 Вт/м | 244.8 Вт | 306 Вт | 250/300 Вт не проходят; 360 Вт — кандидат либо деление по схеме |
| Линия 6 м, два ряда по 12 Вт/м | 144 Вт | 180 Вт | 200 Вт — кандидат; 150 Вт не проходит |

Если в последнем примере паспорт допускает `D=0.8`, БП 200 Вт отдаёт для расчёта лишь 160 Вт и **не проходит** условие 180 Вт; номинал/схему нужно пересмотреть. Не назначать D=0.8 всем изделиям.

Для CCT/RGBW/RGB+CCT хранить максимальную одновременную нагрузку конкретного режима. Нельзя считать, что надпись «14.4W» включает все каналы, или что тёплый/холодный каналы никогда не включаются одновременно, без паспорта/режима контроллера.

### Проверки контроллера

Одновременно должны выполняться:
- допустимое входное U совпадает с используемым U ленты;
- режим и распиновка совместимы;
- `I_channel_j ≤ allowedChannel_j` для каждого активного канала;
- `Σ I_channel_j ≤ allowedTotal` с учётом разрешённых одновременных режимов и derating;
- тип/семейство управления и пульт подтверждены;
- учитываются ограничения общей клеммы, соединителей и ветвей.

Пример необходимости отдельного лимита: 24 В × 6 А = **144 Вт на один канал**, хотя суммарные 15 А дают 360 Вт. Такие цифры также прочитаны на [официальном фото EKS WB5](https://eksmarket.ru/upload/iblock/9cd/kz1vnfnfhkisikl1fhyw2u0nrtbjb081.png) (label_observed), но паспорт партии ещё нужен. Для C01RF [фото EKS](https://eksmarket.ru/upload/iblock/086/risssu9u24wvgggs1e6bk1td18yxb36l.png) дополнительно показывает ограничение круглого входа 5 А при суммарной надписи 12 А: алгоритм должен проверять используемый вход, а не только выходы. Руководство MiBoxer WL5 — справочный пример, не основание OEM-идентичности. [1](https://miboxer.com/light/m_n/pdf/WL5/WL5_FR_V1.0.pdf)

При превышении — несколько подходящих контроллеров/цепей или допустимый усилитель по проверенной схеме. Не подключать выходы параллельно «для сложения ампер» без прямого разрешения производителя.

### Длина, геометрия и тепло

Проверять кратность реза, допустимую длину одного питаемого участка, число точек питания, длину/сечение трасс, ток соединителей и падение напряжения. Катушка 5 м — упаковка, **не универсальный электрический предел** и не правило «БП на каждые 5 м».

Профиль должен принимать ширину/число рядов, обеспечивать допустимый тепловой режим и согласованный оптический результат. IP выбирать по реальному месту монтажа и требованиям, а не только слову «ванная». БП/контроллер должны оставаться доступными для обслуживания; не предполагать достаточное охлаждение в закрытой потолочной полости.

## 7. Матрица совместимости

| Пара | Проверка | При недостатке данных |
|---|---|---|
| Лента ↔ БП | CV/CC, выходное U, нагрузка/ток, условия | needs_review; несовпадающее U — incompatible |
| Лента ↔ контроллер | режим/каналы, распиновка, ток по каналам/сумме | needs_review, не «подходит по 15 А» |
| Контроллер ↔ пульт/панель | точное семейство/протокол, функции, зоны, pairing | needs_review; 2.4 GHz само по себе не доказательство |
| Контроллер ↔ смартфон/голос | модель, firmware, экосистема, сеть, hub/cloud, регион | capability unknown, не активный бейдж Алисы |
| Лента ↔ профиль/экран | ширина/ряды/тепло/геометрия/оптика | запросить профиль и условия |
| Лента ↔ коннектор | ширина, контакты, распиновка, ток, IP/монтаж | не заменять трековым соединителем |
| Ветка ↔ провод/питание | длина, падение напряжения, допустимый ток/защита | инженерный расчёт; не фиксированное сечение для всех |
| Набор ↔ корзина | что уже включено, количество зон/пультов/БП | не дублировать компоненты |
| LED 24 V ↔ CLARUS 48 V / COLIBRI 220 V | разные напряжения и назначение | блокирующая несовместимость, не общий «SMART» |

Проверка технической совместимости не равна проверке наличия, доставки, правовой модели продажи или конечной цены. Показывать основания/ограничения и catalogVersion.

## 8. Все способы управления — без ложных обещаний

| Клиентский выбор | Технический путь | Как предлагать |
|---|---|---|
| Обычное вкл/выкл | подходящий источник/коммутация по проекту | Контроллер не навязывать, если функция не нужна |
| Яркость с пульта | DIM-контроллер + подтверждённый RF/IR пульт | Пульт включён или явно добавлен; показать число зон |
| Тёплый ↔ холодный белый | CCT-лента + CCT-контроллер/пульт | Два световых канала; проверить полную нагрузку |
| Цвет | RGB / RGBW / RGB+CCT в соответствующем режиме | Различать цвет и отдельный качественный белый канал |
| Настенная панель / кнопка | RF-панель либо проводной PUSH/иной вход по паспорту | Проверить вход, питание панели и совместимость |
| Смартфон | Wi-Fi напрямую или RF через совместимый gateway | Не добавлять шлюз повторно, если Wi-Fi встроен; показать зависимость от сети |
| Bluetooth / локальное приложение | конкретный BLE-контроллер и приложение/дальность | По подтверждённой модели; Bluetooth не равен Wi-Fi или Алисе |
| Алиса / голос | проверенная интеграция конкретной модели/экосистемы | Отдельное evidence/стенд; TUYA в имени недостаточно |
| Zigbee | совместимое устройство и hub/координатор | По проекту, пока такого подтверждённого EKS-набора нет |
| Matter | сертифицированное устройство, нужный транспорт и controller | Для Алисы на проверенной справке — Matter over Wi-Fi; Thread не обещать |
| TRIAC/фазовое | специально совместимый диммируемый БП/драйвер и диммер | Обычный недиммируемый БП не считать подходящим |
| 0/1–10 V, DALI/DALI-2, KNX, DMX | специализированный интерфейс/драйвер/декодер, проектная система | Продвинутый путь, не общий switch «умный свет» |
| Адресные эффекты SPI/DMX | совместимый чип/протокол/контроллер, ограничения пикселей/сигнала | Не обещать «бегущий огонь» обычной RGB-ленте |

Технические возможности подтверждаются для связки, а не переносятся между брендами. В текущем feed видны модели RF/WIFI TUYA и 5-in-1 по названиям; наличие в нём подтверждённых DALI/Zigbee/Matter/SPI комплектов не установлено. Функции «без интернета», сохранение режима после выключения, групповое/раздельное управление тоже проверяются отдельно.

**Подтверждение владельца (16.10.2026).** Владелец подтвердил: WiFi-контроллеры EKS, лента и блок питания из его собственного комплекта работают в системе умного дома, включая управление через Алису. Это owner-verified наблюдение по конкретным моделям его комплекта, а не паспортное подтверждение всего ассортимента: список SKU/версий, напряжение, ток по каналам и полная нагрузка в нём не зафиксированы. До привязки к карточкам статус остаётся «проверено владельцем» и не расширяется на другие позиции feed; подбор БП по метражу по-прежнему требует Вт/м и напряжения лент.

Основания: [Arlight о способах управления](https://arlight.ru/support/recommendations/); [1](https://alice.yandex.ru/support/ru/smart-home/supported-matter-devices); [2](https://alice.yandex.ru/support/ru/smart-home/turn-on/zigbee). ## 9. Подбор, цена и заявка

- По умолчанию неизвестный факт не даёт статуса checked. Различать `draft`, `needs_review`, `incompatible`, `electrically_checked`, `stock_checked`, `quoted` — либо независимые оси, а не один вводящий в заблуждение зелёный статус.
- Неполный набор не блокирует обращение: CTA **«Передать на подбор»** с сохранёнными вопросами. Не называть его готовым заказом.
- Для объяснимого кандидата: «БП выбран по нагрузке …, запас …, паспорт/условия …». Не показывать raw-формулы вместо человеческого объяснения.
- Добавления комплектующих показывать до подтверждения: «Для этой зоны нужны…». Удаление обязательного элемента возвращает needs_review, а не тайно добавляет его обратно.
- Смена метража/режима/модели инвалидирует затронутые проверки и quote; изменения состава/суммы выделяются. Ручной выбор сохраняется, пока совместим.
- Intent: только оборудование / потолок+свет / свет в готовое помещение / консультация. Последний не выдать за продажу.
- В lead snapshot: комнаты, features/zones/runs/circuits, source длины и confirmed, выбранное управление, BOM с причинами/статусами, catalogVersion/rulesVersion/quoteVersion, исходные SKU/aliases, включения в ставку и вопросы инженеру.
- Server-side recomputation и проверка quote обязательны перед коммерческим подтверждением; клиентские числа не являются доказательством цены. Идемпотентность/согласие/outbox сохраняются.
- Состав ставок за парящий профиль/линии/карниз утверждает владелец. Материал либо уже включён, либо добавляется, либо учитывается upgrade delta. Не взимать дважды ленту/БП/монтаж. Существующие проценты 10/25% не менять без решения о цене.
