# ПОТОЛКОВО · первая рабочая итерация R7

**14 октября 2026 · отдельная ветка `feat/company-rebrand-v7`**<br>
База: `7f1b5cf8ec686b06d3b36e2991efd08faeb9426b`, после PT-020. Не новая разработка с нуля. Это внедрение бренда и новой главной в действующий Next.js-проект, не отдельный HTML-прототип и не завершение всего ТЗ v7.

## Что внедрено

- Новая главная: интерьерный hero, корпоративное позиционирование, четыре продуктовых решения, существующий расчёт цены, свет, реальные примеры работ, компания, процесс, отзывы и форма.
- Теневые и парящие потолки, световые линии и скрытые карнизы вынесены перед ценовым блоком. Все 9 услуг доступны из меню и отдельной навигации; URL не менялись.
- Палитра тёмно-зелёный / тёплый светлый / лайм, веб-знак ПОТОЛКОВО, новые header/footer, типографика, кнопки и адаптивные сетки. Существующие страницы услуг и каталог получили общую палитру, шапку и корпоративный текст; их архитектура не переписана полностью.
- Основатель показан в блоке компании, а не как единственный исполнитель. Публичная модель — мастера и партнёрские монтажные бригады. ООО, большой штат и новые показатели качества не придуманы.
- Корпоративные тексты в услугах, каталоге, рекомендациях, основных формах и rescue. Проверка copy-lint усилена против остаточных обещаний мастера-одиночки. Цитаты отзывов сохранены.
- Три AI-визуализации с постоянной видимой подписью, реестром происхождения, локальными AVIF/WebP и новым OG. Исходники 1264×848, без апскейла; это не 4K. Их можно заменить собственными оригиналами по инструкции `design/brand/v7/README.md`.
- Существующие фото кейсов не заменены. Новые изображения не приписаны выполненным объектам; примеры работ обозначены как портфолио основателя. Исторические утверждения кейсов требуют проверки по v6 отдельно.
- Сохранены реальный калькулятор, тарифы, расчётные функции, пресеты, черновики, корзина, контекст входа и заявок. Изменение текстов `lib/calculator-flow.ts` не создаёт второе расчётное ядро.
- Мобильное меню содержит все услуги; Escape закрывает его с возвратом фокуса. Desktop disclosure работает с клавиатуры.
- Исправлены найденные проблемы контраста, ARIA рейтинга и клавиатурной доступности горизонтальной таблицы сравнения.
- Добавлен build-time флаг preview для отключения script/noscript Метрики. Сам по себе он НЕ отключает лиды, Telegram, продажу или SMART.
- В `docs/current/` помещены v7 и техническая база v6, README и AGENTS ссылаются на единый индекс.

### Что означают пропуски и границы QA

- 53 DB-теста пропущены без настоящей `TEST_DATABASE_URL`. Это не подтверждение работоспособности боевой БД, outbox и доставки.
- 12 E2E skips обусловлены существующими desktop/mobile условиями набора: мобильный sticky проверяется только на mobile; некоторые сценарии каталога/комплектов — только на desktop. Никакие тесты не удалены ради зелёного результата.
- Playwright проверяет сценарии с моками API. В preview реальная отправка заявок выключена; успешный E2E не доказывает реальную доставку в Telegram/CRM.
- Axe проверял начальные состояния документов, не все комбинации модалок и ошибок. Нет ручного протокола VoiceOver/TalkBack/NVDA, реальных iOS/Android или отдельного Firefox/WebKit-прогона. Полное WCAG-соответствие не заявляется.
- Первые проверки нашли неоднозначный селектор нового теста и дефекты контраста/ARIA; они исправлены. Один промежуточный параллельный прогон дал `ERR_ABORTED` при навигации, одновременно падал процесс снимков. Финальный полный прогон без параллельной съёмки прошёл; точная причина промежуточного сбоя не доказана. Скриншоты далее снимались отдельными браузерными сессиями.
- Скриншоты главной desktop/mobile и блоков решений/реальных работ просмотрены визуально. Автоматические снимки маршрутов — первоначальные экраны, не полноценная ручная приёмка каждой детали длинной страницы.

## Безопасный preview

В текущей сборке и сервере:

```text
NEXT_PUBLIC_PREVIEW_MODE=1
LEAD_API_ENABLED=0
TELEGRAM_LEADS_ENABLED=0
CATALOG_LIVE_FEED2_ENABLED=0
```

Команды запуска — в корневом README. Preview использует snapshot каталога; правдивость остатков/цен этим не подтверждается. Не переносить эти настройки в production автоматически. `NEXT_PUBLIC_PREVIEW_MODE` фиксируется при build: после изменения требуется пересборка.

## Что НЕ закрыто этой итерацией

1. **Не весь v7.** R7-001/004/005/006/007/009/012/015/016/017 продвинуты в пределах описанного выше; полные acceptance этих задач и смежных задач не объявлены закрытыми.
2. Веб-знак — рабочая реализация концепции, не завершённый брендбук, проверка товарного знака или печатные мастера R7-003/018.
3. Каталог сохранён и стилизован. Новый UX фильтров, состояний наличия, комплектов и полностью переработанный калькулятор — следующие этапы с сохранением общего ядра.
4. Нет отдельной новой SMART-посадочной с доказанной BOM/совместимостью, server quote и коммерческим runtime kill switch. AI-визуализация и фраза про управление не подтверждают Алису/протокол для конкретного SKU.
5. Не решены юридические вопросы перепродажи при НПД, договорной стороны и партнёров, согласий/ПДн, сроков/гарантий. Публичный ребрендинг сам по себе не меняет юридический статус.
6. Назначение заявок другим исполнителям, CRM-роли, стандарты партнёров/приёмки и пилот с передачей заказа ещё не внедрены.
7. Существующие v6 вопросы фида, цен, наличия, инженерного расчёта, server quote, безопасности зависимостей и доставки сохраняются. Next.js остаётся **16.3.5**; ребрендинг не заменяет security update и повторную оценку применимости advisories.
8. Предупреждение об устаревшем fallback availability сохранено: фиктивные даты/слоты не создавались.
9. Нет production-деплоя, замера конверсии, реальной end-to-end доставки и утверждения владельцем всех бизнес-claims. Старые URL сохранены; SEO-эффект не измерялся.

## Передача и выпуск

Локальные изменения фиксируются в отдельной ветке. Push и деплой — отдельные действия после безопасного подключения доступа; PAT не должен попадать в чат, URL remote, исходники или логи.

Сначала визуальное согласование текущей итерации → PR → закрытие release-gates v6/v7 и подтверждение владельцем фактов → контролируемый выпуск. Возврат визуального оформления не должен возвращать ложные обещания личного монтажа всех заказов.
