## Выполнено

- Вместо двух дублирующих mobile/desktop-каруселей — одна адаптивная галерея шести существующих решений. Первые два акцента — теневой профиль с треком и парящий потолок с освещением.
- Фильтры «Все решения», «Теневые», «Парящие», «Освещение», «Карнизы» с кнопками aria-pressed, счётчиком и без изменения заказа/хранилища.
- Крупные фотографии, спокойная типографика, фирменные тёмно-зелёный и светлый фоны. Редакторские заголовки отделены от исходных подробных названий.
- Новый просмотр: весь кадр без обрезки, три существующих фото, миниатюры, ссылка на оригинал, стрелки фото отдельно от переключения решений. Выбор следующего решения ограничен текущим фильтром; фото сбрасывается к первому.
- Доступный диалог: focus trap, Escape, возврат фокуса, заголовок aria-labelledby, скролл в коротком viewport, кнопки фото и закрытия не меньше 44×44 CSS px.
- Задача, решение, параметры и расчётный ориентир визуально разделены. Состав бюджета раскрывается отдельно; суммы, скидки, формулы и исходные пресеты не изменены.
- Переход из карточки и диалога сохраняет явный пресет и источники `<slug>:proof-card` / `<slug>:proof`. Полный прежний сценарий 18 м² / 19 м профиля / 10 м трека до заявки пройден.
- Индивидуальная геометрия без пресета ведёт на `/uslugi/individualnye-proekty#action`, а не подставляет типовой потолок. Это намеренное UX-исправление ложного стандартного расчёта.
- Для решений со светом добавлена ссылка на управляемое освещение и оговорка о проверке протокола, оборудования и совместимости для нового проекта. Светильники не добавляются автоматически.
- Удалены три больше не используемых компонента старой карусели и её CSS. Другие разделы не переписаны.

## Контент и ограничения

Сохранены все 18 исходных фотографий шести решений, подписи объектов, исходные факты, бюджеты и пять пресетов. Новые объекты, фото, площади, сроки, отзывы, права на фотографии, история компании или совместимость оборудования не выдумывались. Существующая атрибуция портфолио основателя не является новой проверкой прав. Нет новых публичных URL кейсов: перед их выпуском нужны подтверждённые материалы, права и обязательные поля v7.

Расчётный ориентир не выдаётся за итоговую смету. Сроки подписаны «в примере», а не как обещание для будущего заказа. Исходные утверждения в описаниях объектов требуют проверки владельцем перед production-выпуском.

## Исправленные проблемы проверки

- Тест двух входов был разделён на независимые сценарии: повторный переход на тот же hash не закрывал предыдущий калькулятор.
- Локатор кнопки навигации «Решения» ограничен основной навигацией и точным именем: теперь существуют также фильтр и кнопки деталей с этим словом. Проверки поведения не удалены.
- Локатор исходной карточки в приёмочном тесте заменён на стабильный slug; все проверки параметров и заявки сохранены.
- Убрано пересечение CSS заголовка галереи с заголовком диалога; размер заголовка и touch-target закреплены E2E.
- Предварительный build до первого коммита присвоил всем page-dates дату коммита восстановления после rollback, что задевало прежний тест различия дат. После коммита реализации даты пересобраны из реальной истории: у главной своя дата, у остальных — дата восстановления. Финальный полный Vitest выполнен уже после build и успешен; тест не отключён.

## Выпуск

`main` автоматически запускает production-деплой. Этот этап разрешён только в preview-ветке, без нового PR/merge в main, force-push или production-релиза. Результат локального QA не выдаётся за GitHub CI: текущий workflow не запускается по обычному push в эту preview-ветку.

Далее: согласование галереи владельцем; подтверждённые карточки объектов и права; следующий визуальный этап отдельно. Persistence автономной корзины, юридические вопросы и release-gates v6 не объявляются закрытыми.
