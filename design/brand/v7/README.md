# Визуальная система R7 · изображения

## Что сейчас размещено

Семь AI-визуализаций: три исходных (гостиная с теневым потолком и треком, спальня с контурным светом, кухня со световыми линиями) и четыре для страниц услуг (световые линии в гостиной, скрытый карниз, стандартный потолок, светопрозрачная поверхность). Исходники в `originals/`, описание происхождения/прав/alt — `assets.json`.

Фактическое разрешение каждого исходника — **1264×848**, не 4K. Апскейл не применяется и не считается повышением качества. Это временные качественные интерьерные иллюстрации, а не фотографии объектов ПОТОЛКОВО и не доказательство функций конкретного оборудования. Существующие фотографии кейсов не заменялись.

`BrandPicture` всегда выводит подпись «Визуализация решения», использует локальные AVIF/WebP, srcset/sizes, intrinsic dimensions. Hero загружается приоритетно, остальные иллюстрации — lazy.

## Как заменить своими фотографиями

1. Убедиться в наличии прав, согласий и корректности описания объекта. Желательно предоставить оригиналы не менее 2560 px по длинной стороне, без водяных знаков и пересжатия мессенджером; для полноэкранного/печатного использования нужны отдельные размеры.
2. Поместить исходник в `originals/` и изменить `source`, `alt`, `rights`, `usage` в `assets.json`.
3. Для реальной фотографии указать `kind: "owner-photo"`, достоверный видимый `label` (например, «Фото объекта · [подтверждённое название]»). Не добавлять неподтверждённый адрес или историю проекта. При изменении типа изображения обновить соответствующее ожидание provenance в `tests/company-rebrand.test.ts` — не удалять саму проверку происхождения.
4. Запустить `npm run build:brand-images`. Скрипт делает AVIF (quality 65), WebP (89), варианты до 1920 px без увеличения исходника и отдельный OG 1200×630. Исходник OG — `architectural-living`.
5. Проверить кадрирование на 360/390 и 1440 px, детали потолка/света при 100%, текст подписи, размер файлов и контраст поверх изображения. При смене hero может понадобиться корректировка `object-position` в `app/brand.css`.
6. Закоммитить оригинал, реестр, `data/brand-image-manifest.json` и варианты `public/brand/v7/`. Старые неиспользуемые варианты удалять осознанно после проверки ссылок.

Генератор не запускается в prebuild: замена исходников — отдельное явное действие. SVG-знак в `components/brand/brand-logo.tsx` — веб-реализация выбранного направления, не законченный юридически проверенный пакет товарного знака/полиграфии.


### R7 · новые редакционные страницы

`/o-kompanii` повторно использует `architectural-living`, `/umnoe-osveshchenie` — `floating-bedroom`. Видимая маркировка сохранена. Переключатель сценариев условно меняет CSS-яркость изображения, но не подтверждает работу оборудования. Новых AI-фото команды или выполненных объектов не создавалось.


### R7 · цифровая айдентика и шрифт

- `brand-icon.svg` — цифровой мастер иконки. `npm run build:brand-identity` создаёт `app/icon.svg`, ICO 16/32/48 и PNG 16/32/48/180/192/512.
- `social-covers.json` задаёт 14 обложек. Локальный генератор собирает JPEG 1200×630 и проверяет лимит 200 КБ. Интерьеры подписаны как визуализации; оригиналы в `originals` не заменяются.
- `content/brand-social.ts` связывает route с OpenGraph/Twitter. Старые изображения остаются по прежним URL для обратной совместимости.
- Шрифт Inter сохранён локально под SIL OFL 1.1. Источник, хеши и Unicode-покрытие — `typefaces/provenance.json`; лицензия — `typefaces/OFL.txt` и `/brand/v7/OFL-Inter.txt`.
- WOFF2 применяется через `next/font/local`, TTF — только для генерации графики. Обычной сборке достаточно npm-зависимостей; Python/fontTools/Brotli использовались однократно для подготовки subset, не нужны при `npm run build`.
- Сохранены variable-оси, кириллица/Latin-1, ₽, м², пунктуация и базовые стрелки. Остальные символы могут использовать системный fallback.

Это цифровой комплект рабочего знака, не юридическая проверка обозначения, не финальная верстка печатных носителей и не полный брендбук.
